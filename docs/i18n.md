# 国际化 / Localization

[中文 README](../README.md) · [English README](../README.en.md)

## 中文

- 默认语言为简体中文（`zh-CN`），英文为 `en`。不根据浏览器语言自动覆盖用户的选择。
- 桌面登录页表单上方、移动端登录页品牌右侧、主页面顶栏账号旁提供相同的「中文 / EN」按钮。移动端胶囊视觉高度为 32px，每个按钮保留独立的 44×44px 触控区域。使用原生按钮、目标语言的标签和 `aria-pressed`，支持 Tab、Enter 和空格。
- `LocaleProvider` 管理当前语言，通过 `alethinosplan.locale.v1` 保存本机偏好，并监听 `storage` 事件同步其他标签页。存储失败时，本页切换继续生效并显示提示。
- `src/lib/messages.ts` 集中维护英文词典，以现有中文文案作为稳定键，`MessageKey` 在编译时校验引用。新增文案须同时提供地道英文，避免在组件中拼接中文单位或句子片段；动态值使用 `{count}`、`{title}` 等占位符，数量按需定义 `one` / `other`。
- 错误和通知在状态中保留原始键，到渲染时再翻译，因此已显示的错误或撤销提示也能即时切换。`translateMessage` 仅用于应用自己的消息，不得用于用户输入。
- 日期用显式传入语言的 `Intl.DateTimeFormat` 格式化；存储日期仍为 ISO `YYYY-MM-DD`，日历保持周一开始。HTML 的 `lang`、页面描述和置顶小窗标题同步更新。
- 置顶小窗通过 React portal 继承同一个语言上下文，不重新打开窗口，不重置专注计时。切换语言不重建任务仓库，不改写账号数据。
- 首次生成本地演示数据时采用当前语言；已有示例和用户输入都不随界面切换而重写。登录页的固定产品预览属于界面文案，会跟随切换。
- 浏览器原生日期选择器和表单校验提示可能遵循浏览器或系统语言。Supabase 验证、重置邮件由部署方单独配置，不由前端语言按钮修改。

验证：`npm run check`、`npm test`、`npm run test:e2e`。国际化单元测试位于 `src/lib/i18n.test.ts`，界面回归位于 `tests/i18n.spec.ts`；`tests/i18n-layout.spec.ts` 检查反复切换语言时的控件重叠、容器内裁切、窄屏弹窗和置顶小窗布局。

## English

### Language selection

The default language is Simplified Chinese (`zh-CN`); English uses `en`. The app does not override an explicit preference based on browser language. The same **中文 / EN** control appears above the desktop sign-in form, beside the brand on mobile sign-in, and next to the account menu in the main header. On mobile, the pill is visually 32px tall while each button retains its own 44×44px touch target. Native buttons, labels in each target language, and `aria-pressed` make the control accessible with Tab, Enter, and Space.

`LocaleProvider` stores the preference under `alethinosplan.locale.v1` and listens for storage events to synchronize other tabs. If storage fails, the current page still switches languages and explains that the preference could not be saved.

### Writing translations

`src/lib/messages.ts` is the English catalog, keyed by the existing Chinese source copy. `MessageKey` checks references at compile time. Add natural English for every new message. Translate complete phrases rather than concatenating translated fragments. Use placeholders such as `{count}` and `{title}` for dynamic content, and `one` / `other` variants where a count needs English plural forms.

Errors and notifications retain source keys in state and are translated when rendered, so a message already on screen follows a language change. Use `translateMessage` only for application-owned messages, never for user-authored content.

Dates use `Intl.DateTimeFormat` with an explicit locale. Stored dates remain ISO `YYYY-MM-DD`, and calendars remain Monday-first. The document language, page description, and mini-window title also follow the selected language.

### State and content boundaries

The mini window inherits the same locale context through a React portal. Changing language does not reopen it, reset a focus timer, recreate the task repository, or modify account data. New local demo data uses the language selected at creation time. Existing samples and user input are never rewritten. The fixed sign-in preview is interface copy and does switch languages.

Browser-native date pickers and form validation messages may use the browser or operating system language. Supabase verification and password reset emails are configured separately by the deployment owner; the frontend switch does not change them.

### Verification

Run `npm run check`, `npm test`, and `npm run test:e2e`. Unit coverage lives in `src/lib/i18n.test.ts`, and browser regression coverage lives in `tests/i18n.spec.ts`. `tests/i18n-layout.spec.ts` checks repeated language switching for overlapping controls, clipped containers, narrow-screen dialogs, and mini-window layout.

### README media

Record English-only sample data with `npm run docs:capture -- --locale=en`, then render the animated GIF with `python scripts/render-demo.py --locale=en` (requires Pillow). The capture uses a fresh local browser context, blocks external requests, and produces `docs/assets/demo.en.gif`, `overview.en.png`, `desktop-window.en.png`, and `desktop-focus.en.png`. Chinese assets are left unchanged. Check the GIF frames and both mini-window screenshots before publishing.
