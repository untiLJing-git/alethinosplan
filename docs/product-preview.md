# 首页产品预览：参考与设计取舍

调研日期：2026-10-16。仅依据公开的官方产品页面，不复制视频、图片或代码，也不声称获得了竞品转化数据。

## 观察到的展示方式

- Todoist 官网将任务捕获、专注、规划等功能分区介绍，并提供产品界面与演示视频入口。参考：https://www.todoist.com/
- Things 官网把产品介绍视频与多设备界面截图放在产品说明中。参考：https://culturedcode.com/things/
- Notion Demo Hub 按使用场景组织可自行选择的产品导览，而不是只展示一段通用宣传。参考：https://www.notion.com/product/demos

由此提炼的设计方向是：展示实际产品语汇；每个界面只讲一个小操作；让结果可见。它们并不证明取消试用入口必然提高注册转化，轮换时长及虚化比例也是本项目的设计假设。

## 本次实现

- 正式登录与注册页移除「先体验，不注册」。仅开发环境保留明确的演示 URL，生产构建忽略该参数。
- 用固定内容轮换展示「我的一天 → 规划日历 → 随手记」，不调用任务仓库，不使用账号数据。
- 当前界面在最前方且保持清晰，其他界面退后并轻微虚化；左侧展示区与标题保持有上限的间距，避免高屏上展示区过度下移，矮屏适度压缩间距，主表单保持静止。
- 宽裕的桌面视口在展示区下方增加静态品牌寄语「不必填满每一天。」，用细线与轻量文字收束留白；不增加操作或动画，矮屏与移动端隐藏，不挤压预览和表单。
- 我的一天停留约 3.6 秒，日历和随手记各约 3.2 秒；循环轮换。按当前设计暂时移除播放／暂停按钮，不显示「操作示例」及底部步骤、重播文字，保留输入时自动暂停。
- 撕下部分复用产品里的 800ms 动画，正常通过动画结束事件进入完成画面。
- 用户聚焦输入框、切换账号操作、切走标签页时暂停并保留当前界面在最前方；不会在失焦或返回后自动续播。
- 移动端与桌面端共享自动轮播、点击完成、撕纸和新增笔记动效；移动端保留紧凑的 125px 展示区，不因动画增加表单高度，改变视口宽度不会中断轮播。减少动态效果和密码重置页面仍使用静态展示。
- 不再使用会话级「已看过」标记，轮播不依赖浏览器存储。

## 动效交互约束

当前版本按设计要求保留自动轮播、移除独立播放／暂停控件。输入表单、切换账号操作或切走页面会停止播放，移动端同样播放，减少动态效果模式保持静态；暂停后不自动恢复。输入时暂停并不等同于独立的动效控制，本版本不据此宣称符合完整的动效无障碍要求。

## 后续验证

本次测试验证了轮换层级、暂停时的前景保持、布局、减少动态效果和生产入口限制；尚未验证注册转化效果。上线后应比较表单完成率、首次建任务率与用户对展示的理解，不单独以播放次数评价成功。
